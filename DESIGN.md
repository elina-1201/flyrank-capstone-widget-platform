# Application design

## The high-level design

```mermaid
sequenceDiagram
    participant O as Owner (dashboard)
    participant API as The backend (API)
    participant P as Customer page (browser)
    participant V as Visitor

    O->>API: POST /widgets (authenticated)
    API-->>O: widget saved, id=abc123
    API-->>O: snippet <script src=".../widget.js?id=abc123">
    Note over P: customer pastes that one line into their page
    P->>API: GET /widget.js?id=abc123
    P->>API: GET /widgets/abc123/config
    API-->>P: config JSON (fields, button text, styling)
    Note over P: render the form into a div
    V->>P: fills the form, clicks submit
    P->>API: POST /submissions (cross-origin)
    API->>API: validate → rate limit → spam check → enrich → store → side effect
    API-->>P: 201
```

## Data models (fields, tenancy, indexes)

> All types are PostgreSQL. `timestamptz` = UTC timestamp, `jsonb` = schema-flexible JSON.
> Tenancy rule: every widget and submission query is filtered by `tenant_id`
> (submissions join `widgets`); a tenant can never read another tenant's rows.

### tenants — the widget owner (customer)

| Column | Type | Constraints / notes |
| --- | --- | --- |
| `id` | `uuid` | PK, default `gen_random_uuid()` |
| `name` | `text` | NOT NULL |
| `email` | `citext` | NOT NULL, UNIQUE — login identity |
| `password_hash` | `text` | NOT NULL — bcrypt/argon2 hash; plaintext is never stored (secrets rule) |
| `created_at` | `timestamptz` | NOT NULL, default `now()` |

### widgets — one row per embeddable widget

| Column | Type | Constraints / notes |
| --- | --- | --- |
| `id` | `uuid` | PK, default `gen_random_uuid()` |
| `tenant_id` | `uuid` | FK → `tenants.id`, NOT NULL, indexed — tenancy isolation |
| `public_id` | `varchar(12)` | NOT NULL, UNIQUE — unguessable id in `<script src="…/widget.js?id=…">` (nanoid) |
| `type` | `text` | NOT NULL, `CHECK (type IN ('signup_form','cta','popover'))` |
| `title` | `text` | NOT NULL |
| `description` | `text` | NULL |
| `fields` | `jsonb` | NOT NULL — ordered array of `{name, label, type, required, placeholder}` |
| `button_text` | `text` | NOT NULL, default `'Submit'` |
| `display_options` | `jsonb` | NOT NULL, default `'{}'` — delay, position, once-per-visitor (stretch) |
| `created_at` | `timestamptz` | NOT NULL, default `now()` |
| `updated_at` | `timestamptz` | NOT NULL, default `now()` |

### submissions — one row per accepted visitor submission

| Column | Type | Constraints / notes |
| --- | --- | --- |
| `id` | `uuid` | PK, default `gen_random_uuid()` |
| `widget_id` | `uuid` | FK → `widgets.id`, NOT NULL, indexed |
| `idempotency_key` | `uuid` | NOT NULL, UNIQUE — generated by the widget per attempt; retries land on the same row (shared req: retried action happens once) |
| `payload` | `jsonb` | NOT NULL — validated values only; keys match `widget.fields` names |
| `ip_address` | `inet` | NOT NULL |
| `user_agent` | `text` | NULL — input for the spam heuristic |
| `country_code` | `char(2)` | NULL — ISO 3166-1 alpha-2 from geo provider |
| `region` | `text` | NULL |
| `city` | `text` | NULL |
| `geo_provider` | `text` | NULL — `'ip-api.com'` / `'ipapi.co'`, NULL when all providers are down (fallback evidence) |
| `submitted_at` | `timestamptz` | NOT NULL, default `now()` — time-series axis for the dashboard |

> Honeypot: a filled honeypot is dropped **before** insert (silently rejected), so spam
> submissions produce no row at all.

### submission_events — outbox for the safe side effect

| Column | Type | Constraints / notes |
| --- | --- | --- |
| `id` | `bigint` | PK (identity) |
| `submission_id` | `uuid` | FK → `submissions.id`, NOT NULL, indexed |
| `type` | `text` | NOT NULL — `'confirmation_email'` / `'webhook'` |
| `status` | `text` | NOT NULL, default `'pending'` — `'pending'` / `'sent'` / `'failed'` |
| `attempts` | `int` | NOT NULL, default `0` |
| `next_attempt_at` | `timestamptz` | NOT NULL — worker pickup / retry schedule |
| `last_error` | `text` | NULL |
| `created_at` | `timestamptz` | NOT NULL, default `now()` |

> A worker processes these after the submission is committed. Failure → retry with backoff
> + an alert, and it never blocks the submission response (safe side effect; shared req:
> background job with retries + failure alert).

### Indexes & tenancy summary

| Index | Why |
| --- | --- |
| `tenants.email` (UNIQUE) | login lookup |
| `widgets.tenant_id` | tenant-scoped widget CRUD |
| `widgets.public_id` (UNIQUE) | config lookup by the script URL id |
| `submissions.idempotency_key` (UNIQUE) | constraint, not optional — dedup (retried action happens once) |
| `submissions (widget_id, submitted_at)` | per-widget stats + counts over time; leftmost prefix covers `widget_id` alone |

> Rate-limit counters (per IP and per widget) are **ephemeral** — kept in an in-memory or
> Redis store with a TTL, not in these tables. Persisting every rejected burst would itself
> become an abuse vector.

## Embed flow
| Hop | Who triggers | HTTP | Cached? | CORS | Auth | Failure mode |
| --- | --- | --- | --- | --- | --- | --- |
| Snippet | Owner dashboard | — (returned in API response) | n/a | n/a | required (owner) | cannot configure widget → no snippet |
| Bundle | Customer page | `GET /widget.js` | forever, versioned URL | needed | none | widget absent, page unaffected |
| Config | `widget.js` | `GET /widgets/:id/config` | short `max-age` | needed | none | widget absent |
| Submission | Visitor | `POST /submissions` | none | needed + preflight | none (public) | `4xx`/`429` visible; store-first, side-effects fail-safe |

## API contracts

Three paths, matching the architecture: **public** (no auth, CORS-open), **admin**
(owner CRUD, `Authorization: Bearer <jwt>`), and **dashboard** (owner reads).

> **Error envelope** — every non-2xx is JSON:
> `{ "error": { "code": string, "message": string } }`. The server never returns `500` for
> bad input — validation failures are `4xx` by design.

### Public (unauthenticated)

#### `GET /widget.js` — widget bundle, versioned URL (e.g. `/widget.v2.js` on release)

| Case | Status | Body / headers |
| --- | --- | --- |
| Success | `200` | JS bundle, `Cache-Control: public, max-age=31536000, immutable` |
| Failure | `404` | unknown bundle version |

#### `GET /api/v1/public/widgets/:publicId/config` — widget config

| Case | Status | Body / headers |
| --- | --- | --- |
| Success | `200` | `{ id, type, title, fields, buttonText, displayOptions }`, `Cache-Control: public, max-age=60` |
| Failure | `404` | `{ error: { code: "WIDGET_NOT_FOUND", message: "widget not found" } }` |

#### `POST /api/v1/public/submissions` — visitor submission

| Case | Status | Body |
| --- | --- | --- |
| Success | `201` | `{ id, status: "stored" }` — CORS + `OPTIONS` preflight answered |
| Invalid payload | `400` | `{ error: { code: "VALIDATION_FAILED", message: "…" } }` |
| Oversized payload | `413` | `{ error: { code: "PAYLOAD_TOO_LARGE", message: "…" } }` |
| Unknown widget | `404` | `{ error: { code: "WIDGET_NOT_FOUND", message: "widget not found" } }` |
| Rate limited | `429` | `{ error: { code: "RATE_LIMITED", message: "…" } }` |
| Honeypot filled | `201` | success shape, row **not** stored (silent drop) |

> Enrichment and the side effect never change the status: if all geo providers are down
> or the email/webhook throws, the submission still returns `201` and is stored.

### Admin (authenticated)

#### `POST /api/v1/auth/register` — create tenant

| Case | Status | Body |
| --- | --- | --- |
| Success | `201` | `{ tenant: { id, name, email }, token }` |
| Email taken | `409` | `{ error: { code: "EMAIL_TAKEN", message: "…" } }` |
| Invalid | `400` | `{ error: { code: "VALIDATION_FAILED", message: "…" } }` |

#### `POST /api/v1/auth/login` — get token

| Case | Status | Body |
| --- | --- | --- |
| Success | `200` | `{ token }` |
| Bad credentials | `401` | `{ error: { code: "INVALID_CREDENTIALS", message: "…" } }` |

#### `GET /api/v1/widgets` — list the owner's widgets

| Case | Status | Body |
| --- | --- | --- |
| Success | `200` | `[ { id, publicId, type, title, createdAt } ]` |
| No / invalid token | `401` | `{ error: { code: "UNAUTHORIZED", message: "…" } }` |

#### `POST /api/v1/widgets` — create widget

| Case | Status | Body |
| --- | --- | --- |
| Success | `201` | `{ widget, snippet: "<script src=\"…/widget.js?id=<publicId>\"></script>" }` |
| Invalid | `400` | `{ error: { code: "VALIDATION_FAILED", message: "…" } }` |
| No / invalid token | `401` | `{ error: { code: "UNAUTHORIZED", message: "…" } }` |

#### `GET /api/v1/widgets/:id` — read one

| Case | Status | Body |
| --- | --- | --- |
| Success | `200` | `{ widget }` |
| Not yours / missing | `404` | `{ error: { code: "WIDGET_NOT_FOUND", message: "…" } }` — tenant-scoped, existence not leaked |
| No / invalid token | `401` | `{ error: { code: "UNAUTHORIZED", message: "…" } }` |

#### `PATCH /api/v1/widgets/:id` — update one

| Case | Status | Body |
| --- | --- | --- |
| Success | `200` | `{ widget }` |
| Invalid | `400` | `{ error: { code: "VALIDATION_FAILED", message: "…" } }` |
| Not yours / missing | `404` | `{ error: { code: "WIDGET_NOT_FOUND", message: "…" } }` |

#### `DELETE /api/v1/widgets/:id` — delete one

| Case | Status | Body |
| --- | --- | --- |
| Success | `204` | empty |
| Not yours / missing | `404` | `{ error: { code: "WIDGET_NOT_FOUND", message: "…" } }` |

### Dashboard (authenticated)

#### `GET /api/v1/widgets/:id/submissions?page=1&perPage=50` — paginated submissions

| Case | Status | Body |
| --- | --- | --- |
| Success | `200` | `{ data: [ { id, payload, ip, countryCode, city, geoProvider, submittedAt } ], page, perPage, total }` |
| Not yours / missing | `404` | `{ error: { code: "WIDGET_NOT_FOUND", message: "…" } }` |
| No / invalid token | `401` | `{ error: { code: "UNAUTHORIZED", message: "…" } }` |

#### `GET /api/v1/dashboard/summary` — aggregate stats

| Case | Status | Body |
| --- | --- | --- |
| Success | `200` | `{ totals: { submissions }, byWidget: [ … ], byDay: [ … ], byCountry: [ … ] }` |
| No / invalid token | `401` | `{ error: { code: "UNAUTHORIZED", message: "…" } }` |


## Not building
- drag-and-drop widget creator
- third-party CRM integrations (HubSpot / Salesforce sync)
- custom domains, CDN, or hosted serving — everything runs locally
